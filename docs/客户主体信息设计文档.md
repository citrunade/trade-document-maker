# OCR 单据主体信息提取与数据库字段设计文档

## 一、标准规范说明

### 1. 业务规则

1. **统一识别原则**：只要 OCR/AI 识别出具备企业主体特征的信息（如买方、卖方、目录内企业信息等），
   统一默认判定为「客户」主体，并自动提取对应企业字段信息入库，不做买方/卖方角色区分。
2. **兜底捕获原则**：当单据内容无法明确区分角色时，不做过滤，全部捕获入库，交由用户在审核环节
   人工判断取舍（本软件的 AI 导入功能会先弹出审核表格，AI 识别结果不会未经确认直接写入数据库）。
3. **数据容错与扩展**：除主键 `CustomerID` 外，其余字段均允许为空（Nullable）。地址保持整段文本
   输出，不强制拆分街道/门牌号/邮编，便于直接导出至商业发票等单据。

### 2. 字段清单

| 序号 | 数据库字段名 (DB Field) | 中文释义 (Label) | 数据来源 / 识别规则 | 约束条件 |
|---|---|---|---|---|
| 1 | CustomerID | 客户编号 | 系统生成/手动录入（非扫描识别），格式 `CUST-0001` 顺序递增 | 主键 (PK)，非空 |
| 2 | NameCN | 中文名称 | OCR 智能识别 | 允许为空 |
| 3 | NameEN | 英文名称 | OCR 智能识别 | 允许为空 |
| 4 | CountryRegion | 国家/地区 | OCR 智能识别 | 允许为空 |
| 5 | City | 城市 | OCR 智能识别 | 允许为空 |
| 6 | AddressEN | 英文完整地址 | OCR 智能识别（保持整段文本，不拆分街道/邮编） | 允许为空 |
| 7 | TaxNo | 税号(VAT) | OCR 智能识别 | 允许为空 |
| 8 | ContactPerson | 联系人 | OCR 智能识别 | 允许为空 |
| 9 | Email | 电子邮箱 | OCR 智能识别 | 允许为空 |
| 10 | TelPhone | 联系电话 | OCR 智能识别 | 允许为空 |

### 3. 扩展字段（超出本次 10 字段规范，为兼容外贸单据业务保留）

生成 PI/CI/PL 单据的表头需要「收货人」「通知人」「目的港」三项物流相关信息，
且它们经常与客户的常驻注册地址不同（收货地址 ≠ 账单地址；POD 是具体港口而非城市名），
因此作为客户主体的补充字段一并保留，供制单页面直接引用，不纳入 OCR 的 10 字段强制识别范围：

| 字段名 (DB Field) | 中文释义 | 说明 |
|---|---|---|
| Consignee | 收货人 | 制单时用于 PI/CI/PL 表头，可与地址不同，支持多行文本 |
| NotifyParty | 通知人 | 制单时用于 PI/CI/PL 表头 |
| POD | 默认目的港 | 制单时预填运输条款中的目的港，可在单据中覆盖 |
| Remark | 备注 | 自由文本备注 |

### 4. 架构可扩展性

表结构预留扩展空间，后续如需新增社媒/即时通讯字段（Line、WhatsApp、微信等），
可平滑追加新列（如 `LineID`、`WhatsApp`），无需重构现有基础结构与已有数据。

## 二、建表 SQL 参考（PostgreSQL / MySQL 通用风格）

```sql
CREATE TABLE customers (
    customer_id     VARCHAR(20)   NOT NULL PRIMARY KEY COMMENT '客户编号，系统生成，格式 CUST-0001',
    name_cn         VARCHAR(255)          NULL COMMENT '中文名称，OCR智能识别',
    name_en         VARCHAR(255)          NULL COMMENT '英文名称，OCR智能识别',
    country_region  VARCHAR(100)          NULL COMMENT '国家/地区，OCR智能识别',
    city            VARCHAR(100)          NULL COMMENT '城市，OCR智能识别',
    address_en      TEXT                  NULL COMMENT '英文完整地址，整段文本，不拆分街道/邮编',
    tax_no          VARCHAR(100)          NULL COMMENT '税号(VAT)，OCR智能识别',
    contact_person  VARCHAR(100)          NULL COMMENT '联系人，OCR智能识别',
    email           VARCHAR(255)          NULL COMMENT '电子邮箱，OCR智能识别',
    tel_phone       VARCHAR(50)           NULL COMMENT '联系电话，OCR智能识别',

    -- 以下为外贸制单业务扩展字段，非 OCR 10 字段强制识别范围
    consignee       TEXT                  NULL COMMENT '收货人（制单用，可与地址不同，支持多行）',
    notify_party    TEXT                  NULL COMMENT '通知人（制单用）',
    pod             VARCHAR(100)          NULL COMMENT '默认目的港（制单用，可在单据中覆盖）',
    remark          TEXT                  NULL COMMENT '备注',

    created_at      TIMESTAMP     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at      TIMESTAMP     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '更新时间'
) COMMENT='客户主体信息表（OCR单据提取 + 外贸制单业务共用）';
```

> 说明：本软件当前版本以本地 JSON 文件存储数据（非 SQL 数据库），上述 SQL 作为
> 字段设计的标准参考文档，字段命名与类型可直接用于未来迁移至关系型数据库时的建表依据。
> JSON 存储中对应的字段名采用 snake_case（如 `customer_id`、`name_cn`），与本 SQL 一致。
